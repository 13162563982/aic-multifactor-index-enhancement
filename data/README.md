# Market data: frozen CSI 300 snapshot

Owner: `marketdata` teammate. This directory holds the **frozen real-data snapshot** that
every research run must use, plus (in `tests/fixtures/`) the deterministic offline fixture.

> **Academic/research use only.** All data is scraped from Eastmoney's publicly accessible
> web endpoints. It is used here for a course project; there is no redistribution licence,
> no service-level guarantee and no investment advice. Do not hammer the endpoints; the
> builder is deliberately sequential with polite delays.

## 2. Data sources (Eastmoney public endpoints, token-less)

Hosts are flaky (frequent `RemoteDisconnected`, HTTP 200 with empty payloads), so the
client (`aicwf/data/http.py`) retries with jittered exponential backoff and rotates hosts.
`config/data.yaml` owns the host list, retry ladders and polite delay.

Two transport facts were verified on 2026-11-13 and are worth knowing before rebuilding:

* **IPv6 is broken from this environment.** The hosts advertise IPv6 addresses that reset
  or black-hole connections (measured 1/6 success vs 8/8 over IPv4). Data-fetching
  processes therefore pin `socket.getaddrinfo` to `AF_INET`
  (`RequestsTransport(ipv4_only=True)`, config `sources.eastmoney.ipv4_only: true`).
* **Bursts are rate-limited.** After a few hundred rapid requests all endpoints start
  resetting connections for a few minutes. The builder uses a 0.5 s polite delay and, for
  interrupted/rate-limited runs, a **resumable raw-response cache** at
  `data/cache/<as_of>/` (constituents, benchmark, per-name prices/fundamentals as parquet).
  A restarted build skips cached names; the cache never enters the snapshot directory and
  never affects `snapshot_hash`.

### 2.1 CSI 300 constituents

```
https://{host}/api/qt/clist/get
  ?pn={1..3}&pz=100&po=1&np=1&fltt=2&invt=2&fid=f3&fs=b:BK0500
  &fields=f12,f13,f14,f2,f3,f8,f9,f20,f21,f23,f26,f100
```

`total` is 300 and page size is capped at 100 (3 pages). Field mapping:

| field | meaning | snapshot use |
|---|---|---|
| `f12` | code (e.g. `600519`) | `universe.code` (`600519.SH`) |
| `f13` | market id (1=SH, 0=SZ) | code suffix |
| `f14` | short name | `universe.name` |
| `f2` | latest price | diagnostics only |
| `f3` | pct change (percent) | diagnostics only |
| `f8` | turnover rate (percent) | diagnostics only |
| `f9` | PE (dynamic) | diagnostics only |
| `f20` | total market cap (CNY) | `universe.total_cap` |
| `f21` | free-float market cap (CNY) | `universe.free_cap`, `universe.weight` |
| `f23` | PB | diagnostics only |
| `f26` | listing date `YYYYMMDD` int | `universe.listed_date` |
| `f100` | industry (SW-style) | `universe.industry` |

`universe.weight` is the **normalised free-float market-cap proxy**:
`weight_i = free_cap_i / Σ free_cap` over the covered names (documented proxy for CSI 300
free-float weights; it is not the official index weight file).

### 2.2 Daily bars (qfq adjusted)

```
https://{host}/api/qt/stock/kline/get
  ?secid=1.000300            # index; stocks: 1.600519 (SH) / 0.000001 (SZ)
  &fields1=f1,f2,f3,f4,f5,f6
  &fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
  &klt=101&fqt=1&beg=20160101&end=20261112
  &ut=fa5fd1943c7b386f172d6893dbfba10b
```

**Verified 2026-11-13:** historical bars are served by `push2his.eastmoney.com`. The
`push2*.eastmoney.com` hosts frequently answer HTTP 200 with an empty `klines` list for
historical ranges, so the K-line host rotation is biased towards `push2his`. The `ut`
value is the public constant used by Eastmoney's own web widget — not a secret, login or
API key — and is stored in `config/data.yaml`.

`fields2=f51..f61` returns an 11-field CSV per bar (the shorter `f51..f58` variant has no
turnover/pct change, so the client always requests eleven fields):

| position | field | meaning |
|---|---|---|
| 0 | `f51` | date `YYYY-MM-DD` |
| 1 | `f52` | open |
| 2 | `f53` | **close** |
| 3 | `f54` | high |
| 4 | `f55` | low |
| 5 | `f56` | volume (lots; 手) |
| 6 | `f57` | amount (CNY) |
| 7 | `f58` | amplitude (%) |
| 8 | `f59` | pct change (%) |
| 9 | `f60` | change (CNY) |
| 10 | `f61` | turnover rate (%) |

`fqt=1` = 前复权 (forward-adjusted) prices, current price base. The benchmark uses
`secid=1.000300` (CSI 300 index, `000300.SH`).

### 2.3 Fundamentals history (data centre)

```
https://datacenter-web.eastmoney.com/api/data/v1/get
  ?reportName=RPT_F10_FINANCE_MAINFINADATA&columns=ALL
  &filter=(SECUCODE="600519.SH")&pageSize=60
  &sortColumns=REPORT_DATE&sortTypes=-1
```

One row per report period (last ~60 quarters). Mapped columns:

| source column | snapshot column | note |
|---|---|---|
| `SECUCODE` | `code` | `600519.SH` |
| `REPORT_DATE` | `report_date` | report period end, ISO date |
| `NOTICE_DATE` | `notice_date` | announcement date, ISO date (PIT availability) |
| `EPSJB` | `eps` | basic EPS (CNY) |
| `BPS` | `bps` | book value per share |
| `ROEJQ` | `roe` | weighted ROE (%) |
| `XSMLL` | `gross_margin` | gross margin (%). `MLR` is the gross-profit **amount**, not the margin |
| `TOTALOPERATEREVE` | `revenue` | revenue (CNY) |
| `TOTALOPERATEREVETZ` | `revenue_yoy` | revenue YoY (%) |
| `PARENTNETPROFIT` | `net_profit` | net profit attributable to parent |
| `PARENTNETPROFITTZ` | `net_profit_yoy` | net profit YoY (%) |
| `MGJYXJJE` | `cfo_per_share` | operating cash flow per share |

Announcement dates are **point-in-time** information: a report period becomes usable on
its `notice_date`, never on `report_date`. When `NOTICE_DATE` is missing, the builder
fills `report_date + 90 calendar days` and sets `notice_date_estimated = true` (never
silently using the period end).

## 3. Snapshot artifacts

All tables are sorted as stated below; all date columns are ISO `YYYY-MM-DD` **strings**
(not datetimes) per `docs/artifact_contract.md`. Percent fields keep the source's percent
semantics (e.g. `pct_chg = -2.58` means −2.58%); `ret` columns are decimal fractions.

### `prices.parquet` — `date, code, open, high, low, close, volume, amount, turnover, pct_chg, board`
qfq-adjusted daily bars for every covered constituent from the first trading day of 2016
(or the stock's listing date, if later) to the freeze date. Sorted by `(date, code)`.
`board ∈ {main, chinext, star, bse}` is derived from the code prefix. Bars whose adjusted
close is non-positive (possible for very high-dividend names early in the qfq history)
are dropped and counted in `coverage_report.json.dropped_nonpositive_qfq_bars`.

### `fundamentals.parquet` — `code, report_date, notice_date, eps, bps, roe, gross_margin, revenue, revenue_yoy, net_profit, net_profit_yoy, cfo_per_share, notice_date_estimated`
One row per `(code, report period)` with `report_date <= as_of`. Sorted by
`(code, report_date)`. Missing announcement dates are filled with the 90-day fallback and
flagged. The snapshot stores the full history; the **data-prep stage** applies the
`notice_date <= decision date` filter (see §5).

### `universe.parquet` — `code, name, industry, weight, free_cap, total_cap, listed_date, is_st, board`
The **current** CSI 300 members covered by the snapshot (fetch failures are excluded and
listed in `coverage_report.json`). `is_st` is a real boolean derived from the name;
CSI 300 constituents are not ST names in practice. `listed_date` comes from `f26`, with
the first available bar date as a fallback.

### `benchmark.parquet` — `date, close, ret`
CSI 300 index (`000300.SH`) close and decimal daily return (`ret` first row is NaN).

### `calendar.parquet` — `date`
The trading days covered by the snapshot, derived from benchmark dates.

### `coverage_report.json`
Fetch coverage and caveats: requested/covered names, failed names with errors, price and
fundamental date ranges, dropped non-positive qfq bars, notes. Target coverage is all 300
names; the builder refuses to write a snapshot below 250 covered names.

### `manifest.json`
```jsonc
{
  "schema_version": "1.1.0",
  "as_of": "2026-11-12",
  "created_at_utc": "...",              // only wall-clock value, metadata only
  "source_urls": { "constituents": "...", "kline": "...", "fundamentals": "..." },
  "row_counts": { "prices": ..., "fundamentals": ..., "universe": ..., "benchmark": ..., "calendar": ... },
  "date_ranges": { "prices": ["2016-01-04", "2026-11-12"], ... },
  "files": { "prices.parquet": "<raw sha256>", ..., "coverage_report.json": "..." },
  "content_hashes": { "prices.parquet": "<deterministic content hash>", ... },
  "snapshot_hash": "<hash_json(files)>",
  "provenance": { "builder": "scripts/build_snapshot.py", "source": "eastmoney-public", ... },
  "notes": [ ... ]
}
```

* **`files`** is a flat `filename -> sha256` mapping of the **raw file bytes**. Anyone can
  recompute it from disk to detect post-freeze tampering.
* **`snapshot_hash`** is `hash_json(manifest["files"])` — the canonical SHA-256 of the
  sorted `files` mapping. Downstream stages, run requests and the registry compare this
  single value; it is reproducible from the manifest alone.
* **`content_hashes`** are deterministic `aicwf.util.artifact_hash` content hashes
  (parquet-metadata independent). They are for rebuild-equality checks only — the
  contract forbids using raw parquet bytes as *the* determinism hash. Note that two
  rebuilds on different pyarrow versions can differ in `files` (raw bytes) while having
  identical `content_hashes`.
* Verify a frozen snapshot with `python scripts/build_snapshot.py --check data/snapshots/2026-11-12`
  (or `--as-of 2026-11-12 --verify`).

## 4. Rebuilding the snapshot

```powershell
python scripts/build_snapshot.py --as-of 2026-11-12                 # writes data/snapshots/2026-11-12
python scripts/build_snapshot.py --as-of 2026-11-12 --overwrite     # rebuild in place
python scripts/build_snapshot.py --as-of 2026-11-12 --verify        # verify existing (no rebuild)
python scripts/build_snapshot.py --limit 5 --output C:\tmp\smoke    # debug: 5 names, never for research
```

Runtime: roughly 20–40 minutes sequentially (≈600 HTTP requests with retries) because the
public hosts reset a large fraction of connections. The build streams progress to stdout
(stock counts, failures, ETA). It writes into a temporary `.building` directory and moves
the directory into place only when complete, so an interrupted run never leaves a partial
snapshot at the final path.

Snapshot build caveat: `fqt=1` prices are adjusted against the **current** price base. A
later rebuild therefore produces different adjusted histories even for identical report
periods. The committed frozen snapshot is the single source of truth for a research run;
never mix rows from two snapshots.

## 5. Point-in-time rules (also implemented in `aicwf/data/`)

* The run's `as_of` is a hard information cutoff. `data_prep` drops any snapshot row dated
  after `as_of` and asserts that `panel`, `benchmark` and available fundamentals contain no
  future dates (`aicwf.data.pit.assert_no_lookahead`).
* Fundamentals are available only from `notice_date` (or the `report_date + 90d` estimate
  when missing, flagged `notice_date_estimated`). `aicwf.data.pit.available_as_of` is the
  reusable helper; `pit_audit.json` records the outcome per run.
* Panel construction: suspended days (no bar) keep the previous close forward-filled,
  carry `suspended=True`, zero volume/amount/turnover and `ret=0`; the first return of each
  code in the window is NaN. `log_size = ln(free_float_cap)` uses the freeze-date cap for
  every date (see limitations); `listed_days` is calendar days since `listed_date`;
  `in_universe` marks current members from their listing date onward.

## 6. Known limitations (read before interpreting results)

1. **Current-constituent survivorship bias.** The constituents endpoint returns the
   *current* CSI 300 membership. Applying today's membership to 2016–2026 history excludes
   names that were removed from the index and includes names that joined later. Results are
   therefore an upper-bound-flavoured view of stock selection; the robustness stage runs an
   adversarial "drop top-k winners" stress test to quantify sensitivity. Historical index
   membership is not available from the token-less endpoints used here.
2. **Point-in-time completeness of fundamentals.** Announcement dates are used where
   available; missing dates use a conservative 90-day fallback and are flagged. Fundamentals
   are not restated-history: `columns=ALL` returns the latest reported values for each
   period, not the originally published vintages. Early periods may contain later revisions.
3. **Adjusted prices are not additive across snapshots.** qfq prices are rebased to the
   current price, so returns are correct within one snapshot but price *levels* change if
   the snapshot is rebuilt later. The frozen snapshot plus its `snapshot_hash` pins this.
4. **Non-positive qfq bars.** Very high-dividend names can have negative forward-adjusted
   prices in the early part of the window; those bars are dropped (counted in the coverage
   report) instead of being silently clipped.
5. **Market-cap history is unavailable.** `universe.free_cap` / `total_cap` are freeze-date
   values; `log_size` in the panel is therefore static per code (known at `as_of`, not
   future information, but not point-in-time size history).
6. **Industry classification is the current one** (Eastmoney/SW-style from `f100`) and can
   differ from the classification in force historically.
7. **Suspensions, limit moves and ST status are inferred** from bars/names rather than from
   official trading-state files. `suspended` means "no bar that day"; limit detection is
   left to downstream logic using `pct_chg` and `board` (main 10%, ChiNext/STAR 20%,
   BSE 30%, ST 5%).
8. **Data quality.** Public endpoints can silently serve partial or stale data. The quality
   gates (missing-price ratio, staleness, fundamental coverage, duplicate rows, positive
   prices, as-of cutoff) catch the common cases and record detail in
   `02_data/data_quality.json`; failures raise `DataQualityError` and stop the run.
9. **Licence.** Academic use only; see the header warning.
